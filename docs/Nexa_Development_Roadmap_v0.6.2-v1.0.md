## 1. 产品目标与版本顺序

Nexa v1.0 是面向个人使用的 Local-first 数据中心、跨设备同步平台及 Agent / Automation 控制中心。Windows、macOS 和 Android 各自拥有本地数据库，按同一套数据语义与 Nexa Core 交换变更。首要交付是跨端日常工作流、离线数据可靠性、统一的操作体验，以及可授权、可追溯的自动化。

| 版本 | 优先级 | 版本主题 | 退出条件 |
| --- | --- | --- | --- |
| v0.6.2 | P0 | 架构巩固与移动端准备 | Windows ↔ Core 同步回归通过，现有数据可升级，移动接入契约可用 |
| v0.7.0 | P0 | Android Mobile MVP | 真机可安装，Websites 在 Windows ↔ Core ↔ Android 双向收敛，离线写入和恢复可验证 |
| v0.7.1 | P1 | 移动端核心业务 | Ledger、Websites、Data 日常读写跨端可用，用户能处理同步错误与冲突 |
| v0.7.2 | P1 | 混合液态玻璃、Android 分享、macOS 回归 | 浅深色和低性能模式可用，分享可离线保存，macOS 参与正式同步验收 |
| v0.8.0 | P2 | Agent 与 Automation 中枢 | 任务可调度、可追踪，Action 在授权和审计下执行，高影响动作须经确认 |
| v0.9.0 | 发布门槛 | 可靠性、安全与发布工程 | 长期离线、迁移、备份恢复、凭据吊销与签名发布演练通过 |
| v1.0.0 | 正式发布 | 稳定的 Windows、macOS、Android 产品 | 三端核心工作流和支持矩阵通过，安装、升级、恢复与诊断文档齐备 |

v0.6.2 的范围集中在架构和兼容性。v0.7.0 先跑通真实同步链路，v0.7.1 扩展业务，v0.7.2 再完成视觉与设备入口。v0.9.0 进入功能冻结。复杂 Dashboard 编排、iOS、持续位置追踪、大范围桌面 Local 重写列入后续评估。通知与后台同步分阶段在 v0.8.0–v0.9.0 落地。

### 2.2 设备身份、数据与凭据

- **工作区与安装实例。** 连接配置关联 Core、Workspace、`client_id`、`installation_id` 和本地同步状态。Cursor 按协议的工作区及同步流范围隔离。切换账户或 Core 时独立管理本地数据、Outbox 和 Cursor。账号切换前提示当前待同步变更。
- **首次连接。** 用户填写 Core 地址、测试连接、登录或配对、确认工作区、注册设备，再同步初始数据。第一次配对依赖联网。已完成初始化的设备可在离线时使用已落地的数据和本地编辑功能。
- **凭据。** 配对完成后安全保存 `client_token`，实现更新、失效、重新授权和吊销。Android 在 Keystore 管理加密密钥的方案与 Stronghold 间做真机验证，覆盖重启、升级、备份恢复和密钥失效。避免在普通 SQLite、WebView 持久化存储、日志和诊断包写入明文令牌。正式连接校验 HTTPS 证书。 [Android Keystore](https://developer.android.com/privacy-and-security/keystore) · [Tauri Stronghold](https://v2.tauri.app/plugin/stronghold/)
- **数据契约。** 审计并固化 Ledger、Website、Collection、Record 的实体标识、工作区归属、引用、修订和删除语义。明确账单金额精度、币种、日期与时区，网站 URL 规范化与去重，Collection 字段约束及 Record 与 Collection 的依赖。以现有实现和迁移样例确定最终字段与编码。
- **本地持久化。** Android 将业务表、Outbox、同步元数据和冲突记录存入应用管理的 SQLite。UI 展示本地已提交的数据，并单独呈现其同步状态。合理缩小 Tauri Command 调用范围，Repository 校验输入和工作区上下文。

### 2.3 写入、推送与拉取

1. **本地提交。** 用户创建、修改或删除实体时，用同一 SQLite 事务提交业务变更及 Outbox 操作。事务失败时整体回滚。为操作绑定稳定的幂等标识，并按 v3 契约记录实体、工作区、操作类型与基线修订。
2. **推送。** 同步器按实体依赖和契约顺序读取 Outbox，同一工作区只运行一个同步任务。Core 验证身份、权限、版本及幂等标识，提交业务变更和对应的同步记录。客户端持久化每项结果后确认对应操作。整批响应丢失时以原标识重试，并沿用 Core 已提交的处理结果。
3. **拉取。** 用已提交的 Cursor 分页获取远端变更。每页的变更应用、冲突记录和 Cursor 推进在同一事务中提交。进程中断后从最后已提交的 Cursor 安全重放。比较远端修订和未同步本地变更，按契约合并或登记冲突。
4. **展示。** 连接状态和数据同步状态分别显示。同步页面展示待同步项数、最近成功时间、错误与冲突数量、重试入口。一次操作先获得本地保存反馈，远端确认后更新同步状态。
5. **恢复。** 断网、超时和临时服务故障保留队列并退避重试。令牌过期暂停远端同步并提示重新授权。权限拒绝、数据校验失败和协议不兼容按类别呈现，提供修正、导出或升级入口。修正某条无效操作时按契约创建新的操作或标记原项已处理，后续有效操作按依赖关系推进。

请求路径、字段名、幂等保留期限、Push / Pull 顺序和重试分类均由 v0.6.2 契约确认。

### 2.4 冲突、删除与重同步

| 场景 | 计划行为 | 验证结果 |
| --- | --- | --- |
| 两端从同一旧版本编辑 | 通过 Core 修订或现行 v3 机制检测，按契约自动合并或写入 Conflict Center | 人工处理时可读到本地、远端及差异，选择结果作为新变更同步 |
| 删除遇到离线编辑 | 通过删除标记传播删除。陈旧编辑依规则拒绝或进入冲突处理 | 各端收敛到删除或显式恢复后的状态，保留必要的处理记录 |
| 长期离线，Cursor 失效 | 展示重新同步状态，按协议重新拉取快照或走兼容恢复路径 | 保留未同步 Outbox，重建后逐项重放或提示冲突。恢复期间中断可续跑 |
| Core 已提交，客户端尚未确认 | 用原操作标识重发，再持久化确认 | 服务器业务变更只生效一次，客户端队列最终清空 |
| 同步中被关停 | 从本地已持久化的队列与 Cursor 恢复 | 业务状态、Outbox、Cursor 可追溯到最后一次成功事务 |

删除标记保留期、同步日志保留期与幂等去重窗口需要联合设计，避免超期离线设备写回陈旧数据。兼容范围及超期行为纳入发布说明。账单等高价值数据的冲突策略在契约冻结前单独验收。

### 2.5 Android 生命周期与调度

- **v0.7.0 前台同步。** 应用启动、回到前台、本地修改和手动操作可触发同步。多触发合并，恢复联网时补发。与 Core 通信失败时继续访问本地数据。
- **v0.8.0–v0.9.0 后台同步。** 在真机验证 WorkManager 的网络条件、退避、唯一任务与进程重启恢复。后台入口与前台共用持久化同步状态及互斥机制。WorkManager 周期任务最小间隔为 15 分钟，省电策略和任务条件可能延后执行，因此产品展示最近成功同步时间，并提供立即同步入口。 [Android WorkManager 周期任务](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest)
- **连接恢复与诊断。** 区分设备离线、Core 不可达、认证失效、兼容性错误与冲突。诊断记录版本、错误分类、时间和关联标识，脱敏导出。用户可定位到待处理操作或重新授权入口。

## 3. 混合液态玻璃与移动体验

### 3.1 信息架构

底栏为「首页 · 数据 · ＋ · 自动化 · 我的」。中间的「＋」打开快捷添加面板，按版本开放记一笔、添加网站、添加集合或记录及执行 Action。首页展示 Core 与同步状态、今日摘要、最近活动和快捷操作。数据页集中访问 Ledger、Websites、Collection / Record。「我的」管理 Core、工作区、设备、同步、安全与主题。

| 场景 | 交互要求 |
| --- | --- |
| 首次使用 | 连接检查 → 登录或配对 → 选择工作区 → 初始化同步 → 首页，错误就地说明下一步 |
| 日常新增 | 快捷面板进入表单，保存后立即展示本地结果与待同步状态 |
| 查看与筛选 | 账单、网站、记录使用可滚动的实体表面，支持必要的搜索、筛选和空状态 |
| 异常与冲突 | 从首页状态或「我的」进入同步页，查看队列、失败项和可处理的冲突 |
| 分享到 Nexa | Android 系统分享 → 网站预填表单 → 确认保存 → 本地提交和同步 |

### 3.2 Hybrid Liquid Glass 组件规范

| 元素 | 表面与动效 | 可读性与性能约束 |
| --- | --- | --- |
| 底部导航 | 悬浮玻璃，半透明底色与细边缘高光，选中态有明确对比 | 预留导航栏及安全区，滚动内容可到达末尾。禁用模糊后切到同主题实色 |
| 快捷添加面板 | 单层模糊与遮罩，短促的弹性过渡 | 明确保留返回与关闭入口，关闭后将焦点还给触发控件 |
| Core 状态卡 | 轻玻璃表面，状态图标、文字和最近成功同步时间 | 在线、离线、同步中与待处理状态使用文字和图标辅助颜色 |
| Ledger、Websites、Data 列表 | 主题实体表面、清晰文本、轻量分隔 | 金额、日期、关键字段以及标签在滚动和动态字体下可读 |
| 编辑表单 | 实体输入背景，稳定焦点和错误样式 | 键盘出现时保存及错误信息可达，输入期间布局保持稳定 |
| 弹出层与 Sheet | 边缘透明、高光与柔和阴影，内容区使用易读背景 | 适配系统返回键、焦点顺序和大字体，破坏性操作使用清楚的按钮文字 |

- **浅色。** 蓝白或近中性玻璃，蓝紫仅用于强调。以较深的正文和明确边缘支撑薄底色。
- **深色。** 石墨与深蓝表面，用低亮边缘区分层级，正文保持稳定前景色。
- **主题 tokens。** 统一背景、实体表面、玻璃前景与底色、边框、遮罩、阴影、圆角、间距、字号、动效与模糊档位。建议提供模糊降级和减少动态效果的覆盖项。具体色值和动效参数由 v0.7.2 原型及真机对照定稿。
- **验收。** 在浅色、深色、无模糊模式测量实际背景与普通正文的对比度，目标至少 4.5:1。交互目标至少 48 × 48 dp。用 TalkBack 验证阅读顺序、按钮名称与焦点恢复，并验证字体放大、系统返回、手势替代按钮、刘海屏与软键盘。 [Android 移动端无障碍指南](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility)

### 3.3 Android 分享入口

单独实现 Android 原生 `ACTION_SEND` 文本接收和 Tauri 桥接。首版从分享内容提取 HTTP(S) URL，标题优先使用传入值并允许编辑，描述可选。冷启动缓存待处理的分享直到界面就绪，应用已打开时把新事件送到现有流程。校验 MIME 和输入，处理无 URL、重复投递、已收藏链接和用户取消，保存沿用 Websites 本地事务及 Outbox。图片、附件和通用文本收集后续再扩展。 [Android 接收其他应用分享内容](https://developer.android.com/develop/ui/compose/sharing/receive)

## 4. Agent 与 Automation

以现有 Automation Engine、Agent Data Actions 和 Activity 能力为基础，待 v0.6.2 审计确认可复用边界。Core 负责执行、授权、队列与审计，移动端提供查看、触发、确认和结果入口。

| 子系统 | v0.8.0 开发内容 | 关键约束 |
| --- | --- | --- |
| Automation | 任务定义、触发条件、调度、手动运行、超时、有限重试与历史 | 执行记录区分任务定义、运行实例和重试尝试。对可重试副作用定义幂等键 |
| Agent Center | 展示 Agent、状态、任务、运行历史及关联 Action | 按工作区和角色显示。结果详情提供可读失败原因及可用的后续操作 |
| Action | 声明输入、操作对象、所需权限、风险级别和确认方式 | Core 校验参数、身份、工作区与目标范围，执行前复核有效授权 |
| 审计与活动 | 按运行标识追踪发起、授权、确认、执行与结果 | 记录用户或 Agent、来源设备、时间、工作区、受影响对象和结果摘要。保护敏感输入与凭据 |
| 通知 | 成功、失败和待确认提醒，可打开对应运行详情 | 尊重设备权限与用户设置，通知内容按隐私要求收敛。应用内状态始终可查 |
| Devices / Dashboard | 设备最近上线、同步、可选网络或电池概况，首页可显示 Agent / Automation 状态 | 采集按需授权，区分最后上报时间和当前可达状态。明确数据过期时的展示 |

### 4.1 执行和授权

1. 用户、调度器或经过授权的 Agent 提交任务。Core 创建运行记录，校验 Action 白名单、参数和工作区权限。
2. 对批量修改、批量删除等高影响动作展示对象范围、预计数量和结果预览，使用绑定操作者、具体参数与有效期的确认。范围或参数改变时重新确认。取消、过期、失去权限时结束执行申请并记录原因。
3. Worker 在实际执行前复核权限与确认，记录运行状态。临时失败按上限退避，业务校验失败进入可读的失败状态。发生结果未知或部分成功时，记录已完成范围，并按 Action 的幂等和恢复规则继续。
4. 领域写入沿用业务服务和同步变更路径。客户端能够拉取由 Agent 或 Automation 产生的业务变化，Activity 可追溯到对应运行实例。
5. 成功、失败、取消或待确认状态可在移动端和桌面端追踪。离线时显示已缓存的任务信息，远端执行入口明确提示连接要求。

验收参考链路为「Mac 中通过已授权的 OpenClaw / Agent 集成新增一笔账单 → 经 Desktop Local 或现行集成进入 Core → Android 拉取显示」。集成入口与支持状态由审计确认。未满足前置条件时，使用已支持的 Agent Action 完成等价回归。

## 7. 开发顺序与发布决策

1. **从 062-01 开始。** 以只读方式盘点仓库及现有测试。交付模块路径、入口、实际同步流程、客户端身份生命周期、迁移位置和缺口列表。
2. **完成 v0.6.2 冻结。** 以现有实现和样例确认协议、数据语义、重试与冲突规则。先让 Windows ↔ Core 回归稳定，再接入 Android。
3. **按 070-01 → 070-05 交付第一条全链路。** 依次验证真机构建、本地 SQLite、Core 配对、Push / Pull 和 Windows ↔ Android 离线回归。
4. **扩展业务与移动体验。** 按 v0.7.1 交付日常操作和冲突处理，再按 v0.7.2 完成玻璃组件、系统分享和 macOS 回归。共用协议样例在各端持续执行。
5. **把 Agent 动作纳入现有数据流程。** v0.8.0 按权限、确认、执行、业务数据同步和审计整条链路验收。
6. **冻结范围并发布。** v0.9.0 固化测试数据、设备矩阵、性能目标、兼容窗口、签名渠道与回退方式。v1.0.0 以最终候选构建验证全部发布门槛。
