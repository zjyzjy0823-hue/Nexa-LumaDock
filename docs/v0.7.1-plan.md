## 一、已确认的核心架构与 TBD 冻结

### 1. Shared Space（`/space`）三档安全分级模型

| 安全等级（`tier`） | 典型内容 | UI 查看与编辑 | API 读取与写入 | 存储与加密模型 |
| --- | --- | --- | --- | --- |
| **`standard`（普通共享）** | 日常文本、笔记片段、普通配置、非敏感文件与图片 | 工作区登录后**随时查看/下载/搜索**，无需空间密码 | 支持工作区 JWT、专用 `Space API Token`（`ss_live_`，可分空间/只读/读写），以及在 **Agent Data Actions 白名单显式开启** 后由 Agent 只读访问 | Core 与桌面私有 blob 目录存储（SHA-256 分块校验），按 `workspace_id` 严格隔离 |
| **`protected`（受控机密）** | 需要脚本/服务自动拉取的 API Key、环境变量、受控配置与敏感文件 | **每次读取必重输空间密码**，离页/切后台/登出即清除内存明文 | **仅允许独立签发的细粒度 `Vault Token`（`sv_live_`）** 直读明文（绑定特定空间/条目列表、权限、有效期、强审计日志、可随时吊销）；普通 JWT 无密码、普通 `ss_live_`、Agent `na_live_` 与 Webhook 一律 `403` 拒绝 | Core 以独立环境变量主密钥（`STUDIOLO_VAULT_MASTER_KEY`）做服务端信封加密落库（每修订独立 DEK + AES-256-GCM），UI 访问还须校验用户空间密码哈希（Argon2id） |
| **`e2ee`（极密保险库）** | 根密码、助记词、私钥、绝不允许任何服务端触达明文的私密文件 | **每次读取必重输空间密码**，浏览器/客户端本地解密，离页即清内存 | Core API **仅返回密文块与 `KeyEnvelope(epoch)`**，不提供明文直出接口；调用方需在客户端/CLI 本地使用密码解包 `Space Key` 与 `DEK` 解密 | 纯客户端端到端零知识加密（`Argon2id` + `AES-256-GCM`），Core 永不存储密码、派生密钥或任何明文元数据（文件名/类型/摘要仅存于加密 manifest） |

### 2. 三档权限隔离矩阵（强约束）

| 调用方 / 凭据 | `standard` 读 | `standard` 写 | `protected` 读 | `protected` 写 | `e2ee` 密文同步 | `e2ee` 明文读 |
| --- | :---: | :---: | :---: | :---: | :---: | :---: |
| UI（工作区 JWT） | ✅ 随时 | ✅ 随时 | 🔐 必输本次密码 | 🔐 必输本次密码 | ✅（受设备授权） | 🔐 仅客户端本地输密解密 |
| 专用 `ss_live_`（普通 Space Token） | ✅ 按空间 scope | ✅ 按空间 scope | ❌ 403 | ❌ 403 | ❌ 403 | ❌ 403 |
| 专用 `sv_live_`（机密 Vault Token） | ❌ 隔离 | ❌ 隔离 | ✅ 仅授权空间/条目 + 审计 | ✅ 仅显式写权限 + 审计 | ❌ 403 | ❌ 403 |
| Agent Data Actions（`na_live_`） | ⚙️ 仅白名单显式开启 `space.standard.read` | ❌ 首版禁止 | ❌ 403 | ❌ 403 | ❌ 403 | ❌ 403 |
| Automation Engine / Webhook | ❌ 默认禁止 | ❌ 禁止 | ❌ 403（需人工接续） | ❌ 403 | ❌ 仅后台搬运密文 | ❌ 绝不可达 |

### 3. TBD 冻结基线（TBD-01–04 / 08 / 09）

| TBD | v0.7.1 冻结结论 |
| --- | --- |
| **TBD-01 共享范围** | 首版聚焦 Personal Workspace 内多设备共享；数据库预留 `DeviceGrant` 与 `KeyEnvelope` 结构，便于后续扩展多成员。 |
| **TBD-02 密码学与限额** | AEAD 统一采用 **`AES-256-GCM`**（与 `blobTransfer.ts` 及 WebCrypto 保持逐字节一致）；KDF 采用 **`Argon2id`**（RFC 9106 档位，单次派生在桌面/移动浏览器 ≤ 400ms）；单分块 `2 MiB`，单文件默认上限 `50 MiB`，单空间默认配额 `500 MiB`（环境变量可配）；Core 密文/文件块默认落本地私有目录（可配置路径），与 PostgreSQL 事务元数据引用对齐。 |
| **TBD-03 按次输密边界** | `protected` 与 `e2ee` 的 UI 读取门禁覆盖：查看目录页（`e2ee`）、搜索（`e2ee`）、打开详情、复制 Key、下载文件、查看冲突双方内容与修改提交；一次验证仅服务当次请求，不持久化解锁态。 |
| **TBD-04 忘密与轮换** | `e2ee` 无服务端找回/托管机制并在创建空间时显式警示；常规改密通过 CAS 重包 `KeyEnvelope`；泄露撤销通过新 `Space Key` + 递增 `epoch` 切换，客户端记录已接受最高 `epoch` 拒绝静默回退；`protected` 支持独立轮换 `sv_live_` Token 与修改 UI 空间密码。 |
| **TBD-08 Theme Engine** | 默认主题保持 `white`（纯白），`themeId` 与 `bubbleStyle` 维持设备侧存储，不向 Sync v3 既有 `appearance` 严格对象注入未知字段；既有 `appearance.theme`（`light/dark/auto`）与 `blur/transparency/accent/background` 保持完整映射兼容。 |
| **TBD-09 导入导出与剪贴板** | `standard` 允许自由预览/下载/复制；`protected` 与 `e2ee` 复制 Key 后提供即时提醒与可选定时清剪贴板，明文导出需当次密码确认，不提供公开免鉴权分享链接；暂不做旧 Data 记录自动批量迁移。 |

### Phase 2 · `071-02` Core 三档数据模型、迁移、API 与本地密文仓储
- [ ] **P2-01** 新增 Alembic 迁移 `backend/migrations/versions/0021_shared_space.py`（继承 `0020_fleet_nodes_and_blobs`，兼容 SQLite 与 PostgreSQL）：
  - `shared_spaces`（`id`、`workspace_id`、`name`、`tier` [`standard`|`protected`|`e2ee`]、`active_epoch`、`password_verifier` [仅 `protected` 使用 Argon2id 校验，可空]、`quota_bytes`、`used_bytes` 等）；
  - `space_device_grants`（设备授权与读写边界）；
  - `space_key_envelopes`（`space_id`、`epoch`、`envelope_version`、`envelope_json`）；
  - `space_entries` & `space_entry_revisions`（`entry_id`、`revision`、`entry_type` [`text`|`config`|`key`|`file`]、`epoch`、CAS 版本、普通元数据或加密 manifest）；
  - `space_blobs`（分块存储索引、`sha256`、`size_bytes`、暂存/已提交引用计数与安全 GC）；
  - `space_tokens`（区分 `ss_live_` 与 `sv_live_`、哈希存储、绑定 `space_id`、可选 `entry_ids` 白名单、读写 scope、过期时间与吊销时间）；
  - `space_access_audit_logs`（重点记录 `protected` 读取、`sv_live_` 每次调用、Token 签发/吊销、改密与 `epoch` 轮换，绝不记录明文或密码）；
  - `space_changes` & `space_mutation_receipts`（隔离增量游标与幂等回执）。
- [ ] **P2-02** Core 配置与安全门禁（[config.py](file:///d:/xiangmu/LumaDock/backend/app/config.py)）：
  - 新增 `STUDIOLO_SHARED_SPACE_ENABLED`、`STUDIOLO_SPACE_BLOB_DIR`、`STUDIOLO_VAULT_MASTER_KEY`、`STUDIOLO_SPACE_MAX_FILE_BYTES`、`STUDIOLO_SPACE_DEFAULT_QUOTA_BYTES`；
  - Core 开启 `protected` 写入/读取前强制校验 `STUDIOLO_VAULT_MASTER_KEY` 已正确配置，缺失时明确拒绝且不影响 `standard` 与 `e2ee`。
- [ ] **P2-03** Core REST API（`backend/app/api/space/routes.py` & `backend/app/space/service.py`）：
  - 空间管理：创建/列出/更新/归档三档空间、配额汇总；
  - `standard` 接口：随时列表/搜索/详情/上传下载（支持 JWT 与 `ss_live_`）；
  - `protected` 接口：UI 端提交当次空间密码校验后返回明文/文件流；API 端凭 `sv_live_` 校验空间与条目白名单后解密返回并写入 `space_access_audit_logs`；改密与主密钥信封重包；
  - `e2ee` 接口：`KeyEnvelope` 拉取与 CAS 更新、`epoch` 轮换、密文分块暂存（SHA-256 + 配额检查）、原子提交（旧 `epoch` 强制返回 `409`）、隔离增量游标分页拉取与快照锚点重建；
  - Token 管理与审计接口：签发/列出/吊销 `ss_live_` 与 `sv_live_`（明文 Token 仅签发时返回一次），查看审计日志。
- [ ] **P2-04** Agent Data Actions 白名单集成（[service.py](file:///d:/xiangmu/LumaDock/backend/app/actions/service.py) / [agent_actions.py](file:///d:/xiangmu/LumaDock/backend/app/api/agent_actions.py)）：

  - 负向守卫：`protected` 与 `e2ee` 在服务层硬拒绝任何 Agent / Automation 请求（返回 `403`）。
- [ ] **P2-05** 桌面 Sidecar 本地仓储与独立同步队列：

  - `e2ee` 本地仅存密文块与封套，支持离线按次输密解密。
