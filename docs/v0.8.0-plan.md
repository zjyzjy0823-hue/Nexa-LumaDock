## 一、核心目标与架构边界

`v0.8.0` 只做 **Websites 垂直切片** 的完整离线闭环（`website.category` + `website`），将 Android 从当前「纯在线直连 Core」升级为真正的 **Local-first 原生客户端**，同时保持既有 `/chat` 与 `/space` 直连能力不受破坏：

```text
Vue UI (src/) ── Android 原生壳下 Websites & Sync 走 Tauri invoke() ──▶ src-tauri (薄命令桥 + Android Keystore JNI)
                                                                                  │
                                                                                  ▼
                                                          studiolo-local-core (纯 Rust crate, 无 Tauri 依赖)
                                                          ├── SQLite (sqlx bundled) + 独立本地迁移
                                                          ├── Websites Repository + Outbox 同事务提交
                                                          ├── CredentialVault Trait (Keystore / InMemory)
                                                          └── Sync v3 Client (复用 packages/contracts/rust)
                                                                                  │
                                                                 HTTPS (rustls, nc_live_)
                                                                                  ▼
                                                                     Mac Core (/api/v1/sync/*)
```

### 关键架构决策（开工即固化）
1. **核心离线库与 Tauri 壳解耦**：将 SQLite 仓储、Outbox 事务、配对与 Sync v3 状态机放入独立纯 Rust crate（`src-tauri/crates/studiolo-local-core`），直接依赖 `packages/contracts/rust`（`studiolo-contracts`）。桌面与 CI 无需 Android SDK 即可用 `cargo test` 全量跑通数据库与同步集成测试。
2. **严格遵守双命名与类型红线**：
   - Sync v3 通道（`/api/v1/sync/*`）严格 `camelCase` + 带时区偏移时间戳；
   - Core 配对 REST 沿用现有接口字段，登录使用 `snake_case`，Client 注册、工作区和身份响应保持既有 `camelCase`，请求禁止多余字段；
   - `nc_live_`（同步）与 `nd_live_`（设备遥测）严格隔离，绝不混用，也不使用账号 JWT 执行后台同步。
3. **非回环 TLS 强制校验**：`reqwest` 采用 `rustls-tls`（避免 Android NDK 编译 OpenSSL 坑），公网 Core 强制 HTTPS 证书校验且禁用自动重定向，仅开发测试允许 `127.0.0.1` / `localhost` / `[::1]` 回环 HTTP。

### Phase 2 · `080-02` Rust `sqlx` SQLite 迁移、Websites 仓储与 Outbox 同事务（建议 3–4 人日）
- [x] **P2-01** 落地本地 SQLite 迁移 `migrations/0001_websites_and_sync.sql`（连接启用外键和 WAL）：
  - `local_binding`：单行表，存 `installation_id`、`core_url`、`workspace_id`、`client_id`、`client_name`、`connected_at`、`status`（`disconnected | connected | revoked`）；
  - `local_sync_state`：存 `cursor`、`blocked`、`queue_seeded`、`last_error`、`last_attempt_at`、`last_success_at`、`next_retry_at`；
  - `website_categories`：`id` (UUID PK)、`name`、`sort_order`、`sync_revision`、`deleted_at`、`created_at`、`updated_at`；
  - `websites`：`id` (UUID PK)、`category_id`、`name`、`url`、`description`、`icon`、`tags_json`、`favorite`、`sort_order`、`visit_count`、`last_visited_at`、`sync_revision`、`deleted_at`、`created_at`、`updated_at`；
  - `local_mutations`（Outbox）：`mutation_id` (UUID PK)、`entity_type` (`website.category` | `website`)、`entity_id`、`operation` (`upsert` | `delete`)、`base_revision`、`payload_json`、`depends_on_mutation_id`、`status` (`pending` | `conflict` | `rejected`)、`attempt_count`、`last_error`、`conflict_json`、`created_at`、`updated_at`。
- [x] **P2-02** 实现网站仓储的严格校验与同事务 Outbox：
  - 校验网址协议仅允许 `http` / `https`、字段长度与分类引用有效；
  - 任何 `create / update / delete / visit` 操作与 `local_mutations` 写入在同一 SQLite 事务内原子提交；
  - 合并同一实体尚未发送的 mutation，保留原始 `base_revision` 和 `mutation_id`。首次发送前冻结载荷，后续本地编辑进入依赖它的后继写入；
  - 新建未同步分类下再新建站点时自动写入 `depends_on_mutation_id`，保证推送顺序不触发外键拒绝；
  - 删除采用软删除墓碑（`deleted_at` 非空 + `operation = "delete"` + `data = null`）。
- [x] **P2-03** 添加本地仓储测试，覆盖事务回滚、重开数据库、父子依赖、非法 URL 与删除墓碑。强杀重启纳入真机验收。

### Phase 3 · `080-03` Core HTTPS 配对与 Android Keystore 凭据存储（建议 2–4 人日）
- [x] **P3-01** 定义 `CredentialVault` Trait 与隔离键规则：
  - 存储键严格按 `(core_url, workspace_id, kind: client | device, identity_id)` 命名空间隔离；
  - Rust 测试环境提供 `InMemoryVault`；
  - Android 端通过 Tauri Android Kotlin 插件/JNI 接入 **Android Keystore**（生成不可导出 AES-256-GCM 密钥，加密 `nc_live_` / `nd_live_` 后写入 `noBackupFilesDir`，绝不打印日志、绝不回显明文给 WebView）。
- [x] **P3-02** 实现 Core 配对流程，沿用 [Android 凭据与配对决策](android-auth.md)：
  - 校验 Core URL（公网必须 HTTPS，禁止用户名/密码/路径片段，禁止重定向）；
  - 按序执行：`GET /api/health` → `POST /api/v1/auth/login` → `GET /api/v1/workspace`（返回 Personal Workspace 供用户确认）→ `POST /api/v1/clients/enroll`（`platform: "android"`，若同 `installation_id` 已存在且未吊销则改走 `POST /api/v1/clients/{id}/credential` 轮换）→ `GET /api/v1/client/me` 验真；
  - 验真通过后原子写入 Keystore 与 `local_binding`，立即释放内存中的用户密码与临时 Core JWT；
  - **绑定防串库保护**：若本地已有不同 `(core_url, workspace_id, client_id)` 的同步状态，拒绝直接覆盖同步；已吊销 Client 重新注册返回 `409` 时不自动复活，引导创建新副本并保全旧副本 Outbox。
- [x] **P3-03** 使用本地模拟 Core 验证配对确认、同一身份轮换、401 阻断、吊销后保留队列。

### Phase 4 · `080-04` Rust Sync v3 引擎（前台推拉、冲突与快照恢复）（建议 3–5 人日）
- [x] **P4-01** 实现 `SyncV3Client`（同步通道模型复用 `studiolo-contracts`）：
  - 固定附带 `Authorization: Bearer nc_live_...` 与 `protocolVersion = 3`；
  - 处理 `409 sync_protocol_mismatch`、`409 sync_in_progress`、`401`（标记需重新授权并停止自动重试，保留全部 pending 队列）、网络超时（不误判为密码错，记录退避时间）。
- [x] **P4-02** 实现增量拉取（Pull）：
  - 循环 `GET /api/v1/sync/changes?cursor=N&protocolVersion=3&limit=100` 直到 `hasMore == false`；
  - 单页事务应用 `website.category` 与 `website`（忽略 `v0.8.0` 暂未本地落表的其他实体类型但正常推进 `cursor`），遇本地同实体存在 `pending` mutation 时保留本地草稿并转为 `conflict`（写入远端快照 `conflict_json`）。
- [x] **P4-03** 实现幂等推送（Push）与部分失败处理：
  - 按 `depends_on_mutation_id` 拓扑序分批 `POST /api/v1/sync/mutations`（断网重试严格复用同一 `mutationId`）；
  - 处理 `results[]`：
    - `applied`：更新本地实体 `sync_revision` 并清除 Outbox 行；
    - `conflict`：标记 `status = 'conflict'` 并保存远端快照；
    - `rejected`：标记 `status = 'rejected'` 与封闭 `reason`，提供本地 `dismiss`（放弃并级联跳过依赖项）与 `retry`（用新 `mutationId` 基于当前数据重建）。
- [x] **P4-04** 实现游标失效快照重建（Resync）：
  - 收到 `400 {"resyncRequired": true, "workspaceRevision": R}` 时，先更新 `last_error = "resync_required"`；
  - 事务内应用快照条目并保存快照游标。保留快照中缺失的本地行和草稿，远端版本与本机待提交基线不一致时记录冲突。遇 `409 snapshot_expired` 重开分页会话，再拉取快照版本之后的增量。
- [x] **P4-05** Rust 契约模拟覆盖多页拉取、幂等重放、冲突、部分拒绝、删除墓碑与 `resync_required` 恢复。

## 三、推荐开工节奏

建议按「**先纯 Rust 闭环验证，再接 Android JNI/UI 与 CI 出包**」顺序推进，风险最低：
1. **Sprint 1（Phase 1 + Phase 2）**：搭建 `studiolo-local-core` crate + `sqlx` SQLite 迁移 + Websites/Outbox 同事务仓储 + `cargo test` 全绿；同步补齐 GitHub Actions Android APK CI；
2. **Sprint 2（Phase 3 + Phase 4）**：完成 `CredentialVault` + `CorePairingService` + `SyncV3Client`（推拉/冲突/快照恢复），用 `cargo test` 跑通完整 Sync v3 状态机与边界测试；
3. **Sprint 3（Phase 5）**：接 Android Keystore Kotlin 桥、Tauri Commands 与 Vue 前端 Websites/Sync 路由，CI 出包并在真机完成 Windows / macOS / Mac Core / Android 收敛验收。
